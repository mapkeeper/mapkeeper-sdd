## UC1 — 매장 정보 변경

### ✅ F-01 상대 날짜 처리 실패

- [x] **재현**: "내일 하루 쉽니다." → 10초 후 변경안 없이 입력 화면 복귀, "입력 내용을 다시 확인해 주세요."
- [x] **원인 ①** `adapters/intent.py`의 `_CLOSURE_WORDS` 정규식이 `쉬`만 인식 → "쉽니다"(쉽 ≠ 쉬)에서 매칭 실패, 규칙 파서가 포기
- [x] **원인 ②** `adapters/gemini_proposal.py` 프롬프트가 *"내일", "다음 주 월요일" 같은 표현은 확정 날짜를 알 수 없으므로 빈 배열을 출력한다* 로 상대 날짜를 **명시적으로 금지** → 모델도 `[]` 반환 → 422
- [x] **원인 ③** 프론트 `safeUserMessage()`가 `VALIDATION_ERROR`를 무조건 "입력 내용을 다시 확인해 주세요."로 덮어씀
- [x] **해결 ①** 종결어미 변형(`쉽니`, `쉼`, `휴업`, `영업 안 해요` 등) 인식 추가
- [x] **해결 ②** 프롬프트에 **오늘 날짜(Asia/Seoul)와 요일**을 주입하고, 상대 날짜를 확정 날짜로 계산하도록 지시 변경
- [x] **해결 ③** 서버가 만든 안내 문구를 그대로 노출 — 예시를 포함한 실행 가능한 문구로 교체

### ✅ F-02 복합 요청 일부가 조용히 누락됨

- [x] **재현**: "9월 1일은 임시 휴무이고 주차는 불가능합니다." → `임시 휴무`만 표시, `주차 정보` 누락 안내 없음
- [x] **원인 ①** `parse_intent()`가 첫 번째로 읽힌 항목만 튜플 하나로 반환하고 즉시 종료 (메뉴 → 주차 → 휴무 → 영업시간 순 단락 평가)
- [x] **원인 ②** 누락 자체를 감지·전달하는 경로가 아예 없음
- [x] **해결 ①** 파서가 읽을 수 있는 **모든 항목을 누적**해 반환 (복수 변경안)
- [x] **해결 ②** 문장이 언급했지만 변경안에 담기지 못한 항목을 `unmappedRequests`로 계산해 API 응답에 포함
- [x] **해결 ③** 파서가 일부만 읽었고 남은 언급이 있으면 모델에 재요청 — 모델이 더 많이 담으면 그 결과를 채택
- [x] **해결 ④** 검토 화면에 "‘주차 정보’ 요청은 이번 변경안에 담지 못했어요" 안내 배너 노출

### ✅ F-03 생성 중 처리 단계가 보이지 않음

- [x] **재현**: 명확한 임시 휴무 요청도 변경안까지 약 20초, 스피너만 표시
- [x] **해결** 단계형 진행 표시 컴포넌트 도입 — `✓ 요청 내용 확인 / ● 날짜와 변경 항목 정리 중 / ○ 변경 전후 비교 준비`
- [x] **해결** 경과 시간별 추가 안내(10초/20초/30초)

## UC2 — AI 홍보문구 생성

### ✅ F-04 리뷰 0건인데 긍정 키워드가 표시됨

- [x] **재현**: `분석한 리뷰 총 0건` + `#맛있는메뉴 #친절함 #다시찾는집`, 생성 결과에도 그대로 반영
- [x] **원인** 백엔드는 리뷰 0건일 때 키워드를 빈 배열로 정확히 반환하지만, 프론트 `SeoGenerationWizard.tsx`의 `fallbackKeywords`가 빈 배열을 하드코딩 키워드로 **덮어쓰고**, 그것이 `seedKeywords`로 전송되어 프롬프트의 "반드시 고려할 키워드"가 됨
- [x] **해결 ①** `fallbackKeywords` 제거 — 키워드가 없으면 표시하지 않고 빈 상태 안내만 노출
- [x] **해결 ②** `seedKeywords` 계약을 `minItems: 1` → `0`으로 완화하고, 비어 있으면 프롬프트에서 키워드 줄 자체를 생략
- [x] **해결 ③** 결과 화면 해시태그는 리뷰 키워드가 없을 때 **모델이 사장님 답변에서 뽑은 키워드**만 사용

### ✅ F-05 "질문 3개" 안내와 실제 질문 수 불일치

- [x] **재현**: 목적 선택 화면 "질문 3개 · 약 1분 소요" → 실제로는 `4/4`
- [x] **해결 ①** 안내 문구를 "기본 질문 3개 · 약 1분 소요 / 필요하면 확인 질문 1개가 더 있을 수 있어요"로 교체
- [x] **해결 ②** 기본 질문은 항상 `n / 3`으로 고정, 추가 질문은 `추가 질문` 배지로 명확히 구분

### ✅ F-06 일정 지식이 없어 사용자가 날짜를 반복 입력함

- [x] **재현**: "추석 연휴 정상 영업합니다." → AI가 시작일·종료일을 다시 질문
- [x] **해결** 한국 공휴일·연휴 표(2026~2027) 도입 — "추석 연휴"를 `2026-09-24 ~ 2026-09-26`으로 해석
- [x] **해결** 확인 문구를 "2026년 추석 연휴인 9월 24일부터 9월 26일까지가 맞나요?" + `맞아요` 한 번 클릭으로 전환
- [x] **한계 명시**: 현재는 내장 표. 실서비스는 공공데이터포털 특일 정보 API·학사일정 연동 필요 (백로그)

### ✅ F-07 소식 유형별 질문 템플릿 부족

- [x] **재현**: 추석 정상 영업 소식인데 "어떤 혜택이 있는지 말씀해 주세요" → 없는 혜택을 만들도록 유도
- [x] **해결** 유형별 질문 템플릿 도입

| 소식 유형 | 질문 |
|---|---|
| 공휴일/연휴 영업 | 정상 영업 여부 → 영업시간 → 안내할 메뉴 |
| 임시 휴무 | 휴무 날짜 → 재개 날짜 → 전달할 안내 |
| 신메뉴 | 메뉴명·특징 → 판매 시작일 |
| 할인 행사 | 대상 메뉴·할인 내용 → 기간 |
| 학교 행사 | 관련 일정 → 추천 메뉴·대상 고객 |

- [x] **해결 ④** 원본으로 되돌리기
- [x] **해결 ⑤** 편집 내용이 실제로 저장되도록 `PATCH /seo/generations/{id}/drafts` 신설 — 편집 후 승인하면 편집본이 게시됨 (기존에는 편집해도 원본이 게시될 구조였음)

### ✅ F-09 플랫폼별 문구 차이가 드러나지 않음

- [x] **해결** 결과 화면을 **플랫폼 탭(구글/네이버/카카오)** 으로 전환, 탭마다 실제 생성된 개별 문구·키워드·작성 기준 표시 (소식·소개글 공통)
